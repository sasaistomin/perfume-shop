# DeLas Parfume — магазин парфумів (React + Node)

Сайт зроблено за макетом із Figma (головна, каталог, товар, кошик, «Історія») з адаптивом під телефон, планшет і ПК.
Сторінку з 3D-моделлю свідомо не робили.

## Запуск

```bash
npm install
ADMIN_PASSWORD=ваш_пароль npm run dev
```

- Магазин: http://localhost:5173
- Адмінка: http://localhost:5173/admin

**Бойова версія** (все на одному порту):

```bash
npm run build
ADMIN_PASSWORD=ваш_пароль npm start      # http://localhost:3001
```

У Windows (PowerShell): `$env:ADMIN_PASSWORD="ваш_пароль"; npm run dev`

> Якщо пароль не задати, буде `admin123`. Обов’язково змініть його перед публікацією.

## Адмінка

- **Замовлення**: повна інформація (покупець, телефон, адреса, коментар, кожна позиція з брендом, об’ємом, ціною й сумою, промокод, знижка, пакування, разом), історія статусів, пошук і фільтр, кнопки копіювання телефону й адреси, попередження про товар, що закінчується.
- **Товари**: назва, бренд, опис, теги, об’єми (мл, ціна, склад), фото (завантаження), **ноти з фото**, **парфумер із фото та біографією**, приховати, вибраний, новинка.
- **Відгуки**: нові відгуки з’являються на сайті лише після схвалення. Позначку «Покупка підтверджена» ставите ви.
- **Підписники**: ті, хто заповнив форму «Зареєструйтесь».
- **Промокоди**: створити, вимкнути, видалити (стартовий: `DELAS10` на −10%).

## Доставка

У формі замовлення покупець обирає **відділення Нової пошти**, **поштомат** або **кур’єра** та вводить місто з підказками.

- **Без налаштувань**: підказки міст беруться з вбудованого списку (~60 міст), номер відділення чи поштомату покупець вписує сам.
- **З ключем Нової пошти** (рекомендовано): підказки по всіх населених пунктах, а також **повний список відділень і поштоматів** обраного міста.
  Ключ безкоштовний: особистий кабінет novaposhta.ua → Налаштування → Безпека → API-ключ.
  Задайте його змінною `NOVA_POSHTA_API_KEY`.

В адмінці в кожному замовленні видно спосіб доставки, місто та відділення/поштомат або адресу кур’єра (з кнопками «скопіювати»).

## Публікація на Vercel + Supabase (рекомендовано)

Сайт працює на **Vercel**, а замовлення, товари, відгуки й фото з адмінки зберігаються в **Supabase** (безкоштовний тариф).
Локально все працює як раніше — з файлом `server/data/db.json`.

### 1. Supabase
1. supabase.com → **New project** (регіон — Frankfurt / eu-central-1). Запам’ятайте пароль бази (сайту він не потрібен).
2. **SQL Editor → New query**, вставте й натисніть **Run** (це робиться один раз, сам сайт SQL-запитів не надсилає):

```sql
create table if not exists public.kv (
  key text primary key,
  value jsonb not null,
  version integer not null default 1,
  updated_at timestamptz not null default now()
);
alter table public.kv enable row level security;
```

   `row level security` без правил означає, що читати таблицю ззовні не може ніхто — лише ваш сервер із секретним ключем.
3. **Project Settings → API Keys** (або **API**): скопіюйте
   - **Project URL** (вигляд `https://xxxx.supabase.co`);
   - **secret** ключ (`sb_secret_…`) або старий **service_role** ключ. Нікому його не показуйте.

Кошик для фото `uploads` сайт створить сам при першому завантаженні фото в адмінці.

### 2. Vercel
1. У Терміналі в папці проєкту: `npx vercel login`, потім `npx vercel` (на питання — Enter).
2. vercel.com → проєкт → **Settings → Environment Variables** → додайте:
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_SERVICE_ROLE_KEY` — секретний ключ;
   - `ADMIN_PASSWORD` — пароль від адмінки;
   - (необов’язково) `NOVA_POSHTA_API_KEY`.
3. `npx vercel --prod` — готово. Адмінка: `/admin`.

Змінити пароль: змініть `ADMIN_PASSWORD` у Vercel і зробіть `npx vercel --prod` (або Redeploy). Старі входи стануть недійсними.
Усі замовлення можна побачити й у самому Supabase: Table Editor → `kv` (усе зберігається одним JSON-записом `delas:db`).

> Запасний варіант без Supabase: Vercel → Storage → Upstash for Redis + Blob (змінні `KV_REST_API_URL`, `KV_REST_API_TOKEN`, `BLOB_READ_WRITE_TOKEN` підхоплюються автоматично).

## Інший хостинг (VPS, Railway, Render)

Потрібен хостинг, який запускає **Node.js 18+** (звичайний «хостинг для HTML», GitHub Pages чи Netlify не підійдуть — там немає сервера, і замовлення нікуди не збережуться).
Підходять: VPS (Hetzner, DigitalOcean, Hostinger VPS тощо), Railway, Render, Fly.io.

**Команди:**
- збірка (Build): `npm install && npm run build`
- запуск (Start): `npm start`

**Змінні середовища** (у панелі хостингу, розділ Environment / Variables):

| Змінна | Що це |
|---|---|
| `ADMIN_PASSWORD` | ваш пароль від адмінки (довгий, 12+ символів) |
| `DATA_DIR` | папка на **постійному диску** для бази та фото, напр. `/data` |
| `TRUST_PROXY` | `1`, якщо хостинг стоїть за проксі (Render, Railway, Nginx) — щоб ліміти запитів працювали правильно |
| `NOVA_POSHTA_API_KEY` | ключ Нової пошти для підказок відділень (необов’язково) |
| `PORT` | зазвичай хостинг задає сам |

⚠️ **Важливо про диск.** На багатьох хмарних хостингах файли, записані програмою, зникають при перезапуску.
Підключіть постійний диск (Render → Disks, Railway → Volumes, на VPS це не потрібно) і вкажіть його шлях у `DATA_DIR`,
інакше замовлення та завантажені фото пропадуть після оновлення сайту.

**Зміна пароля:** змініть `ADMIN_PASSWORD` у панелі хостингу та перезапустіть сайт. Усі старі входи в адмінку одразу стануть недійсними.

## Безпека адмінки

- Вхід тримається в **HttpOnly-cookie** (Secure, SameSite=Strict): JavaScript на сторінці токен не бачить, у localStorage його немає.
- Кожна зміна даних вимагає заголовок `X-Delas-Admin` — підробити запит з іншого сайту (CSRF) не вийде.
- Сесія живе 8 годин. Зміна `ADMIN_PASSWORD` або `SESSION_SECRET` миттєво розлогінює всіх.
- Підпис сесії залежить від `SESSION_SECRET`, пароля та ключа бази — знаючи код з GitHub, підробити вхід неможливо.
- На опублікованому сайті **адмінка не вмикається**, якщо пароль не задано, коротший за 12 символів або містить admin / vercel / delas тощо.
- 5 невдалих спроб входу — блокування на 15 хвилин, кожна невдала спроба уповільнюється.
- Заголовки безпеки: CSP, HSTS, X-Frame-Options, nosniff, Permissions-Policy (у `vercel.json` і на сервері).

Обов’язково задайте у Vercel `SESSION_SECRET` — випадковий рядок (Термінал: `openssl rand -hex 32`).

## Безпека замовлень (і чому тут немає SQL)

У проєкті **немає SQL-бази взагалі**: дані лежать у JSON-файлі `server/data/db.json`, тому SQL-ін’єкції неможливі в принципі.
Додатково сервер:

- сам рахує ціни, знижку й суму (ціни з браузера ігноруються), перевіряє наявність на складі;
- перевіряє кожне поле (довжина, формат телефону й e-mail, посилання на фото);
- обмежує кількість запитів (замовлення, відгуки, підписка, вхід в адмінку);
- приймає лише справжні PNG, JPG і WebP (за вмістом файлу, SVG відхиляються), до 5 МБ;
- записує файл бази атомарно, тож він не пошкодиться при збої.

**Резервна копія**: просто скопіюйте папку `server/data` (там база й завантажені фото).

## Фото

Фото з макету лежать у `public/images/site` (сторінки) та `public/images/products` (товари).
Щоб замінити фото сторінки, покладіть файл із **тим самим ім’ям** (наприклад `hero.jpg`).
Фото товарів, нот і парфумерів завантажуйте через адмінку.
